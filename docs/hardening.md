# حماية حدود Cloudflare و Firebase (دليل التنفيذ)

الكود تم تعديله ليصرف أقل. الباقي إعدادات في لوحات التحكم عندك، مرتبة بالأهم.

## ما اتغيّر في الكود (ومُختبر)
| قبل | بعد |
|---|---|
| كل زيارة لأي صفحة = قراءة Firestore (إعدادات الصيانة) | الزائر العام على الرئيسية/كيف يعمل/الخدمات = **صفر قراءات** (اختبار Playwright يثبت ذلك) |
| الإعدادات والخدمات والنصوص القانونية بتتقرا من جديد مع كل تحميل | محفوظة في المتصفح: إعدادات 5 د، خدمات 30 د، قانونية ساعة |
| قراءة "هل هو أدمن" مع كل تحميل لكل مستخدم | تتحفظ 15 دقيقة |
| كل زائر جديد يحمّل Turnstile ويصرف طلب Worker | App Check يبدأ **فقط** عند الدخول/التسجيل/أي قراءة من Firebase (قيس قبل/بعد) |
| صفحة العامل تقرا حتى ~40 طلب + قراءات القواعد | حتى ~24 |
| خطوط Google (طلب خارجي يحجب أول رسم) | خطوط محلية + preload |
| ملفات `.map` منشورة | غير منشورة |

## تقدير السعة على Firebase Spark (تقدير من قراءة الكود، مش قياس حي)
| الفعل | قراءات تقريبية |
|---|---|
| زائر عام يقرا صفحات | 0 |
| تحميل صفحة كاملة لمستخدم مسجّل | 3 إلى 4 |
| فتح صفحة طلبات العامل | 25 إلى 50 (يعتمد على عدد خدماته ونطاقه) |
| عميل ينشر طلب | 4 قراءات + 3 كتابات |
حد Spark = 50,000 قراءة و 20,000 كتابة في اليوم. بمتوسط (3 تحميلات + 2 فتح طلبات للعامل) يعني حوالي **700 عامل نشط يومياً** أو حوالي **1,400 عميل**، يعني نحو **1,000 مستخدم نشط يومياً** قبل أن تقف القراءات. عند الوصول للحد يتوقف Firestore كله حتى منتصف الليل (توقيت المحيط الهادئ).

## 1) الأقوى: Blaze + سقف مصروف (خطوة واحدة، تكلفتها شبه صفر)
Blaze يحتفظ بنفس الحصة المجانية، وما بعدها بسعر ~ $0.06 لكل 100 ألف قراءة. يعني 500 ألف قراءة زيادة في اليوم ≈ $0.30. الموقع **لا يقف** عند الحد.
1. Firebase Console > Usage and billing > Modify plan > Blaze (يحتاج بطاقة).
2. Google Cloud Console > Billing > Budgets & alerts > أنشئ ميزانية (مثلاً $5/شهر) مع تنبيه عند 50% و 90% و 100%.
3. هذا لا يوقف الصرف تلقائياً. لو عايز "قاطع طوارئ" فعّل `maintenanceMode` من لوحة الأدمن عند أول تنبيه.
القرار قرارك: القالب الحالي (`docs/read-budget.md`) كان مكتوب فيه "Blaze فقط بموافقة صريحة".

## 2) App Check: يمنع أي حد من حرق قراءاتك بسكربت
القراءات العامة (الخدمات، الإعدادات) مفتوحة بمفتاح الـ API العلني. أي شخص يقدر يكرر الطلب 2,000 مرة ويحرق 50 ألف قراءة في دقائق. App Check يرفض أي طلب مش جاي من موقعك.
1. فعّل القيم `VITE_WORKER_URL` و `VITE_TURNSTILE_SITE_KEY` في البناء الإنتاجي (متعمل فيها الكود جاهز).
2. Firebase Console > App Check > Firestore > اترك الوضع **Unenforced** أسبوع وراقب "Verified requests" مقابل "Unverified".
3. لما تكون نسبة Verified قريبة من 100% اضغط **Enforce**. لو فعّلته قبل التأكد، المستخدمين الحقيقيين ممكن يتحجبوا.
(تطبيق Auth enforcement اختياري ولا ننصح به الآن.)

## 3) Cloudflare (التفاصيل خطوة بخطوة في docs/setup-steps.md)
- **Pages (الموقع الثابت)**: طلبات وعرض نطاق غير محدودين في الخطة المجانية. لا قلق.
- **حد الـ builds (500/شهر)**: عطّل النشر التلقائي من Git واستعمل Deploy Hook من الـ CI (لا يمكن استعمال wrangler مع مشروع مربوط بـ Git). كده الـ build يحصل فقط للنسخ اللي نجحت اختباراتها.
- **Worker (100,000 طلب يومياً)**: لم يعد يستهلكه الزوار العاديون. اربط دومين خاص بالموقع وبالـ Worker، وفعّل قاعدة rate limit المجانية الواحدة (20 طلب/10 ثواني لكل IP، هذا حد الخطة المجانية) على `api.yourdomain.com`، وBot Fight Mode (من غير استثناءات)، وأغلق `workers.dev` بعد التحويل (`workers_dev = false`).
- حدود القاعدة المجانية: بالـ IP فقط، لا تحمي من هجوم موزّع.

## 4) CSP (سياسة المحتوى): جاهزة، في وضع المراقبة
أضفتها في `public/_headers` كـ `Content-Security-Policy-Report-Only`: **لا تحجب أي شيء**. افتح الموقع وسجّل دخول بجوجل واستعمل كل الصفحات مع فتح F12 > Console، وأي سطر يبدأ بـ `[Report Only]` يعني شيء كان هيتحجب. لو مفيش شيء بعد أسبوع، غيّر الاسم إلى `Content-Security-Policy` (واحذف `-Report-Only`) ودمج `frame-ancestors` فيها.
مهم: لو الـ Worker على دومين خاص، أضفه في `connect-src`.
اختبرت الصفحات العامة ووجدت وأصلحت حالة واحدة (اختبار الاتصال الداخلي من Firestore إلى `google.com/images/cleardot.gif`). ما قدرتش أختبر **تسجيل الدخول بجوجل** ولا **الإشعارات** لأنها تحتاج حسابات حقيقية، وده سبب الإبقاء على وضع المراقبة.

## 5) مراقبة مستمرة
- Firebase Console > Usage: قراءات/كتابات اليوم.
- نفّذ `LIVE_URL=https://helpnear.pages.dev npm run test:live` بعد كل نشر (CI يعملها تلقائياً).
